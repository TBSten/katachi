KATACHI-126ガターが { } の無いクラスのメンバの違反を出さない（deny by default）

deny by default の Role で allow(data, `class`, "*Entity") だけ書くと、ガターの ◆ は Allowed なのに check では主コンストラクタの val が違反になる。IDE と Gradle の答えが食い違う

今
// 定義: allow(data, `class`, "*Entity")   // { } 無し、deny by default◆ data class UserEntity(          // ガター: Allowed      val id: String               // check: 違反（`val` は allow されていない）  )// 説明（explainKtFiles）はトップレベルの宣言しか見ないため
案（どれにするかは要相談）
案 A: 説明をメンバまで下ろし、◆ のツールチップに「メンバ 1 件が違反」を出す案 B: トップレベルの ◆ を「Allowed（メンバに違反あり）」の別アイコンにする案 C: deny by default でも { } 無しならメンバを暗黙 allow（検査側を変える）// A / B は KATACHI-93（メンバの ◆）と同じ土台
リスク・デメリット
  • 利用者案 C は検査を緩めるので「書いていないものは禁止」の原則が崩れる。A / B はガターの情報量が増える
  • 利用者直るまでは「IDE で緑なのに CI で落ちる」体験が続く（deny by default の Role で起きやすい）
  • ライブラリDeclarationExplaining をメンバまで再帰させると説明の件数が増え、定義 JSON と IDE のキャッシュのサイズ・速度に影響。golden テストの更新
