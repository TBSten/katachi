KATACHI-185ポチポチして一般的なユースケースの Role を定義できるビルダー

ktFileContent の DSL（required / allow / anythingElse）を覚える前に、よくある Role の定義をチェックボックスで組み立てて、出てきたコードを貼りたい

今
docs のガイドを読み、DSL の語彙を覚えて手で書く"ViewModel".role {  ktFileContent {    required(`class`, fileName)   // どの関数・引数を使うかを自分で調べる    allow(...)  }}
案（イメージは本文のトグル）
[x] 命名規則  suffix: ViewModel[x] 指定されたプロパティのみ  uiState: StateFlow<*UiState>[x] 命名規則に合うメソッドのみ  prefix: on[x] private 宣言を許可→ "ViewModel".role { ktFileContent { ... } } がその場で出る。OK 例 / NG 例も
リスク・デメリット
  • 利用者ビルダーで表せない細かい規則は結局手で書く。ビルダーの出力と手書きが混ざると、どこを直せばよいか迷う
  • ライブラリDSL を変えるたびにビルダーも直す（docs の中の JS）。IDE に置くなら IDE プラグインの話になり、当面 docs に書かない方針とぶつかる
