ツール似ている点違う点
eslint-plugin-boundaries ★elements の pattern + capture でファイルに type を付ける。no-unknown-files でどの type にも入らないファイルを禁止。element-types は default: disallow にできるESLint ルール。import の向きだけを見る。文書・生成・差分なし
Deptrac ★collector でコードを layer に分ける。layer 間の依存は既定で全部禁止。uncovered（どの layer にも入らない依存）を報告・--fail-on-uncovered。skip_violations と Graphviz 図単位はクラスと依存。置き場所・名前は見ない
dependency-cruiser ★allowed ルールに無い依存は違反（not-in-allowed）。dot / mermaid / d2 / html の図。known-violations で baseline。--affected で git 差分から影響範囲import の単位。役割に名前を付ける仕組みは正規表現のグループだけ
Nx（module boundaries・generators・graph・affected）project に tag を付け、depConstraints の許可リストで縛る。生成器・グラフ・affected まで 1 つの workspace から単位はプロジェクト。中のファイル配置は見ない
Turborepo Boundaries ★tag ごとに dependencies / dependents を allow / deny（実験的）。turbo gen と --affected もあるパッケージ単位
Sheriff ★tagging のパスに <domain> を書くと値を取り出して tag にする（katachi の capture）。depRules・index.ts で公開範囲依存とカプセル化だけ
Steiger（Feature-Sliced Design） ★layer / slice / segment という決まった役割の語彙でフォルダ構成を検査（no-segmentless-slices など 21 ルール）FSD 専用。自分で役割を定義する道具ではない
Spring Modulithトップレベルパッケージをモジュールとみなし verify()。同じモデルから C4 / PlantUML 図と Module Canvas。internal は既定で外から触れない規約ベースで DSL は無い。単位はパッケージ
ProjectGuard ★restrictModule は許可リスト外を禁止。baseline、HTML レポート、Mermaid の依存図Gradle モジュールと外部ライブラリの依存だけ
Freeletics Gradle plugins ★モジュールの置き場所（app / core / domain / feature:*:implementation）で種類が決まり、checkDependencyRules で種類ごとのルール。ファイル名でモジュールを自動 includeFreeletics の構成専用
modules-graph-assertモジュール名の正規表現で allowed / restricted、グラフの高さの上限、Graphviz 出力モジュール依存だけ
ArchUnit ★layeredArchitecture、ensureAllClassesAreContainedInArchitecture（どの layer にも入らないクラスを違反に）、FreezingArchRule（baseline）、PlantUML 図をルールとして使うクラスの単位。ファイルや非 Kotlin ファイルは見ない
Konsist / Konture ★テストで構成を検査。Konture はモジュール依存・命名と baseline宣言外を違反にはしない（書いたルールだけ検査）
jMolecules / jQAssistant役割（stereotype / concept ラベル）をコードに付けて、それを元に検査や文書を作るアノテーションやグラフ DB 経由。置き場所は主役ではない
Sonargraph / SonarQube Architecture意図したアーキテクチャを定義し、実際の依存とのずれを報告（SonarQube は 2025 年末から Java・JS/TS・Python・C#）商用。依存が主役
Tach ★宣言していない依存はエラー。public interface、tach show でグラフ、tach reportPython の import 単位
import-linter / PyTestArchlayers / independence / forbidden の契約依存だけ
thai-lint（file placement） ★global deny で「src/ と tests/ 以外の .py は禁止」が書ける。ディレクトリごとの allow / deny正規表現だけ。役割の概念なし
folderslint ★許可するディレクトリのパスを並べる（* / **）。並べた以外は違反フォルダだけ。ファイルの役割なし
ls-lint ★ / eslint-plugin-check-fileディレクトリごと・拡張子ごとの命名、exists で個数名前の書き方が中心
go-arch-lint ★component をパスの glob で定義し mayDependOn の許可リスト。graph コマンドGo のパッケージ依存
Packwerk ★package.yml を置いたフォルダがパッケージ。宣言していない依存・private 定数の参照を違反に。package_todo.yml（旧 deprecated_references.yml）で棚上げRuby の定数参照単位
Rails + Zeitwerkapp/models など役割の決まったディレクトリ、rails generate、zeitwerk:check（ファイル名と定数名の一致）フレームワークの固定規約
ArchUnitNET / NetArchTest / NsDepCop / Harmonize各言語版の ArchUnit / Konsist。NsDepCop は許可した名前空間依存だけ通す依存とクラスの性質
TuistSwift の manifest から Xcode プロジェクトを生成、tuist graph、scaffold テンプレート、暗黙の import の検査構成の生成が主役で、置き場所の検査は弱い
Bazel / Pantsvisibility は既定で private（Deny by default）。BUILD でパッケージを宣言ビルドの単位
Structurizr / LikeC4 / Context Mapper / JHipster JDLDSL でアーキテクチャやドメインを宣言し、図やコードを出す実コードとの検査はしない（Context Mapper・JDL は生成側）
CODEOWNERS / Backstage / Nx ensure-ownersパスに持ち主を付ける。ensure-owners は持ち主のいないものを違反にする役割ではなく持ち主
Plop / Hygen / Angular schematics雛形からファイルを作る生成だけ。検査とつながらない
