## 0. Preparation

**What the `katachi` command does (`doctor`, `scaffold`, `lint`, `katachi agent test`), leave to it.** Do not redo it by hand, and do not supplement the steps with workarounds of your own.

You are only responsible for judgment in the following:

- Step 1: Analyzing the codebase and confirming the writing preferences
- Step 3: Writing and refactoring the `architecture { }` definition
- Step 4: Deciding whether to fix or leave remaining architecture violations
- Step 6: Proposing which Roles to give a template, and applying the review
- Step 6-A / 6-B / 6-C / 6-D: Planning a sample task, wiring up CI, setting up documentation generation and templates

**Do not rewrite the `build.gradle.kts` generated by `scaffold`, or the `settings` / root build file / `gradle/libs.versions.toml` it appended to.** `ProjectArchitecture.kt` is the exception, since it is what you fill in during step 3. Adding `processors { }` to the `katachi { }` block of `build.gradle.kts` is allowed only in 6-C, once the user has agreed (6-D needs no change to it).

### Before you start — clear the session (only if it applies)

This is not a checklist item; it carries no number.

**If this session already holds a lot of unrelated conversation, say so to the user first.** These steps run from 0 to 6, with dozens of exact commands along the way, and step 3 reads documentation. The more unrelated context is in the way, the easier it is to skip a step, invent a workaround nobody wrote down, or carry an assumption over from the earlier topic.

**Suggest it, do not decide it.** If the user chooses to carry on, carry on.

Clearing also throws away what you have read so far, so include the text below when you suggest it. Pasting it into a fresh session starts again from the same place.

```
Install katachi in this project with the katachi skill.
```

If they want to pin the working directory, they can add "use <path> as the working directory".

There are three points in these steps where the session may end (the end of step 6, the end of 6-0, and the end of each of 6-A to 6-D). Each of them says how to resume.

If there is a working directory made by an older katachi (by `katachi agent init` or `katachi-install.sh`), its checklist may lack items these steps use. Make a new working directory from this skill's templates (0-2), and carry over only what you need from the old one. While both are below the project root, the `katachi` commands stop and ask which one to use: once you have carried things over, ask the user to move the old one out of the project, or prefix the commands with `KATACHI_WORKDIR=<the new one>`.
