## 6-C. (After reporting in 6) Set up documentation generation

Do this only if the user wants it.

**Before you start, read the documentation generation page.** It is at https://tbsten.github.io/katachi/guides/document-generation/ . What the generated pages contain and how to write the output location (`outputDir`) are there. The Role you have to declare when you move the output is in step 3 below, and what `--arg mode=check` does is at the end of 6-B. Do not fetch the whole site (llms-full.txt).

1. Write `title = "..."` and `description = "..."` at the top of `architecture { }` (skip this if you did in 3-2). They become the heading and body of the root page.
2. Generate with `./gradlew :architecture-test:katachiDocs` and check `architecture-test/build/katachi/docs/`.
3. **Propose to the user whether to commit the generated pages.** The default output is under `build/`, so nothing is committed. To commit them, put all three of the following in place. If any one is missing, the test or CI fails, or the documentation silently goes stale.
   - Set the output directory in the `katachi { }` block of the verification module's `build.gradle.kts` (leave the `architecture = ...` line as it is)

     ```kts
     katachi {
         architecture = "..."
         processors {
             docs {
                 outputDir = rootProject.layout.projectDirectory.dir("docs/architecture")
             }
         }
     }
     ```

   - Declare that location as a Role in `layout { }`. Without it, `gitTracked()` picks the generated pages up and `:architecture-test:test` fails with `[UnexpectedFile]` / `[UnexpectedDirectory]`. Cover both the index `README.md` and the `*.md` for each Role and group

     ```kt
     "ArchitectureDocs".role {
         summary = "Pages generated by katachiDocs"
         description = "Pages generated by katachiDocs. Not written by hand"
         layout {
             "docs" {
                 "architecture" {
                     "README.md".file()
                     "**" / "*.md".file()
                 }
             }
         }
     }
     ```

   - Run `--arg mode=check` in CI (the end of 6-B)

   **Do not use a name that matches `.gitignore`, such as `build` or `out`, for the output directory** (same as 3-3; pages you thought you committed would be ignored).

   **The output directory becomes katachi's.** Any `*.md` in it that this run did not generate is deleted. Do not point it at a directory holding handwritten Markdown.
4. Generate again, and confirm `katachi agent test` passes.

Record the files you created or changed in `changedFiles`, then mark `6-3` done.

> **The session may end here.** The next session finds the working directory (the directory with `check-list.html` below the project root), reads the checklist's JSON, and goes on from there: from the first item that is not done, or, once step 5 is done, from what the user asks for (6-0, or one of 6-A to 6-D). The sections are in the table in `references/setup/README.md`. The previous session's results are in the checklist and the report; if `tmp/katachi-command.txt` is there, run katachi the way it says (0-1). Do not rely on the conversation's memory.
