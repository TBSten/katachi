KATACHI-85ignore() の場所を必ずドキュメントに出す

documented = false の group に ignore() を書くと、理由の残らない除外が 2 行でできてしまう。「除外には必ず理由が残る」という原則 3 が守られていない

今
"Tools".group {  documented = false        // ドキュメントに出ない  "Scripts".role { layout { "scripts".ignore() } }   // summary も無い}// scripts/ は検査されず、生成ドキュメントのどこにも理由が出ない
案（full.md 2746 行）
## 検査対象外の場所| Path     | Role    | Why                || scripts/ | Scripts | ⚠ summary が無い   |// documented に関係なく一覧に出す。summary が無ければ Warning// .module { } が注入する "build".ignore() は一覧から除く（v0.5 で .module { } ごと消える）
リスク・デメリット
  • 利用者ドキュメントを外したくて documented = false にした group が一覧に出る。既存の定義で Warning が増える
  • ライブラリ利用者の ignore() と katachi が足した ignore() を区別する印が要る（.module { } の削除後は不要になる見込み）。生成ドキュメントの差分で mode=check が落ちる
