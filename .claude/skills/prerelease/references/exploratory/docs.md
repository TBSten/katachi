# チャーター: docs

- 利用者像: katachi を初めて知った学習者
- 場所: クラウド
- 目安: 45 分

手順 6（全ページ巡回）は「全ページを機械的に見て壊れを探す」。13 は**ページを読んで、書いてあるとおりに自分でコードを書く**ところを見る。

## 観点

- 初めて: トップから入って、`get-started` の順に読む。迷ったところ・飛ばしたところを記録する
- 移行: v0.3 の利用者として、リリースノートと移行のページを頼りに書き換える
- わざと間違える: コードの例をそのままコピーして貼る。動かないコピペが無いか
- 環境違い: 幅 390px・ダーク・日本語と英語を切り替える

## 入口

- 使ってよい: 6-1 で配信しているビルド済みの docs（ローカルの URL）・mavenLocal の katachi
- 使わない: 本番の https://tbsten.github.io/katachi/（リリース前なので古い）・リポジトリの mdx の直読

## やってみること

- 「入門」だけを頼りに、題材を 3 つ書く（例: レイヤー分離・命名規則・ファイルの置き場）。各題材で、ドキュメントから**コードをコピーして**自分のプロジェクトの写しに貼り、動かす
- ページ間の「次に読むもの」の導線で、同じ内容を 2 か所で別々に説明していないか
- 検索（Pagefind）で、利用者が使いそうな言葉を 10 個引く（「ignore」「baseline」「enum」「移行」など）。目的のページが出るか
- 用語の揺れ（同じものを別の言葉で呼ぶ）・日本語と英語の意味の違い
- API リファレンスから docs のガイドへ、ガイドから API リファレンスへ、迷わず行き来できるか
