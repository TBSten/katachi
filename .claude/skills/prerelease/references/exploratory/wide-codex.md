# チャーター: 広域（Codex）

- 利用者像: katachi を導入して、定義を書き、検査を回し、レポートと docs まで一通り使う人（コンポーネントで区切らない）
- 場所: Mac（Codex。クラウドには入っていない。nightly では回さない）
- 目安: 30 分（Codex の利用枠の上限に 1 セッション約 20 分で達した実績がある。KATACHI-407 の試し）

コンポーネント別のチャーター（クラウド・並列）が「その領域を深く」見るのに対し、これは**領域を限定せず**、Claude の探索者が見ていない所を広く探す遊撃。
Claude の探索者が書いた「やったこと」と「触れなかったところ」を先に渡し、**被らない所を優先**する（[exploratory.md](../exploratory.md) の「Codex を足す」）。

## 観点

- わざと間違える: 境界条件（オプションの組み合わせ・スラッシュや空文字を含む名前・通常ファイルとディレクトリの衝突・2 回目の実行・別の値での再実行）
- 案内に従う: エラーメッセージや「次はこうしてください」の案内を**そのまま実行**して、直るか（案内どおりにして直らない型）
- 手順書と実際: 入門・README・`--help` の記述と、実際の挙動・出力の食い違い
- 指示に無い細かい所: 文言の揺れ・出力の順序・終了コード・メッセージの重複や欠落・既定値の表示

## 入口

- 使ってよい: 9-1 の配布物だけ（`bin/katachi`・mavenLocal の katachi・6-1 のビルド済み docs）。利用者と同じ入口にする
- 使わない: リポジトリの `build/` や `src` の直接実行（9-1 の配布物と同じ形だけを使う）、本番のサイト
- 隔離する: 配布物の写しと専用の作業ディレクトリ・Gradle home・`.m2` を渡し、`git` の操作・写しの外への書き込みを禁止にする

## やってみること

- Claude 側の「触れなかったところ」から 5 つ選んで、まず触る（無ければ、観点ごとに 1 つずつ）
- `katachi` の各サブコマンドで、オプションを**組み合わせて**（`--force`・`--save`・`--console`・`-x` など）、案内されたとおりに直るかを確かめる
- 入門のページどおりに題材を 1 つ書き、途中で出たエラーの案内を実行する
- Claude 側が書いた発見と同じ症状を見つけたら、別の条件（別のパス・別の値）で再現するか確かめる
- **例にない操作を最低 3 つ試す**
