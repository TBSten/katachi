# 結果の index.html と、利用者向けの TODO.html

[SKILL.md](../SKILL.md) の「7. 報告」の詳細。チェックリスト（Markdown）とは別に、人が最初に開く HTML を2枚作る。
どちらも `.local/release-v<版>/` の直下に置く。外部依存なしの1ファイル（CSS / JS はインライン）、`file://` で開ける、
ライト / ダークの両方で読める、幅 390px でも横にはみ出さない。

## TODO.html — 利用者がやること・決めることだけ

**チェックの途中から作り、状況が変わるたびに言われなくても更新する**（subagent が1体返るたび・利用者が判断を返したたび・
新しい警告が出たたび）。7 の報告で初めて作るのではない。

- 雛形: [templates/TODO.html](../templates/TODO.html)。`{版}` などを埋め、見本の項目を消して使う
- 載せるのは**利用者の手が要るものだけ**。区分は次の5つ。各区分の件数を冒頭の pill に出す
  1. リリース前に直すか決める（priority 7 以上。放置すると利用者が詰まる）
  2. 判断してほしい（方針が要るもの。選択肢とおすすめを添える）
  3. 目を通してほしい（リリースノート、軽微な警告の一覧、ドキュメントの変更の提案）
  4. 操作してほしい（push・publish・利用者の開発サーバーの再起動など、エージェントがやらない／やれないもの）
  5. 決定済み・対応中（利用者が答えたもの。消さずにここへ移し、🔧 対応中 / ✏️ 編集済み・検証中 / ✓ 済 を付ける）
- 1項目 = 見出し1行 + 本文1〜2文 + 「決めてほしい:」の1行。根拠やリンクは `<details>` に入れる
- 各項目の `data-id` は項目ごとに一意にし、更新しても変えない（チェックの状態がブラウザに残っていて、それと結び付く）
- 末尾に「いま走っているもの・待っているもの」を1行
- 利用者の回答はチャットで受ける（HTML のチェックは利用者の覚え書き。エージェントは読まない）

## index.html — 結果をひとまとめにしたもの

7 の報告の直前に作る（チェックの途中で作り直してもよい）。チェックリストより先に開かれる前提で、first view で全体が分かるようにする。

- 雛形: [templates/index.html](../templates/index.html)。TODO.html と同じ見た目
- 冒頭: 版・対象のコミット・日時、結果のバッジ（✅ / ⚠️）、リリースノートの概要（7 の報告と同じ 3 文）、TODO.html へのリンクと件数
- 手順ごとのカード（1〜6・8・9-1・9-2）: 結果の1行（例: 「13 / 13」「要検討 0 件」「priority 7 以上 0 件」）、状態の色、
  成果物へのリンク（`visibility-check.md`・`docs-vs-impl.md`・`site-crawl.md`・`ci-checks.md`・`install-kit.md`・`install-e2e.md`・
  `screenshots/`）。詳細は `<details>`
- 重要な警告（priority 7 以上）: タイトルと1〜2文。TODO.html の該当項目と同じ内容
- 軽微な警告: 件数と、手順ごとの内訳だけ（本文は各成果物へ）
- 数字や件数はチェックリストと同じものを使う（2箇所で数え直さない。チェックリストが SSoT）
