# 結果の index.html と、利用者向けの TODO.html

[SKILL.md](../SKILL.md) の「7. 報告」の詳細。チェックリスト（Markdown）とは別に、人が最初に開く HTML を2枚作る。
どちらも `.local/release-v<版>/` の直下に置く。外部依存なしの1ファイル（CSS / JS はインライン）、`file://` で開ける、
ライト / ダークの両方で読める、幅 390px でも横にはみ出さない。

## TODO.html — 利用者がやること・決めることだけ

**チェックの途中から作り、状況が変わるたびに言われなくても更新する**（subagent が1体返るたび・利用者が判断を返したたび・
新しい警告が出たたび）。7 の報告で初めて作るのではない。

- 雛形: [templates/TODO.html](../templates/TODO.html)。`{版}` などを埋め、見本の項目を消して使う
- 載せるのは**利用者の手が要るものだけ**。区分は次の5つ。各区分の件数を冒頭の pill に出す
  1. リリース前に直すか決める（priority 7 以上。放置すると利用者が詰まる）
  2. 判断してほしい（方針が要るもの。選択肢とおすすめを添える）
  3. 目を通してほしい（リリースノート、軽微な警告の一覧、ドキュメントの変更の提案）
  4. 操作してほしい（push・publish・利用者の開発サーバーの再起動など、エージェントがやらない／やれないもの。13 の IDE plugin の観点カード = 利用者が 15 分触る 5 つの観点もここ）
  5. 決定済み・対応中（利用者が答えたもの。消さずにここへ移し、🔧 対応中 / ✏️ 編集済み・検証中 / ✓ 済 を付ける）
     - 「直さない」「このまま」「後で」「方針」の答えは、ここへ移すのと同じタイミングで [decisions/](../decisions/README.md) に書き足し、
       項目の末尾に「→ decisions/<ファイル> に記録」と書く。書き足さないと、次の回で同じことを聞く
- 1 項目の形（利用者の指定、2026-11-20）:

  ```
  [p9] [コンポーネント] 内容          [コピー]
  本文 1〜2 文

  決めてほしい
  - [ ] (a) …（おすすめ）
  - [ ] (b) …
  - [ ] (c) …
  一言（任意）

  ▸ 詳細
  ```

  - 見出しは priority のバッジ・コンポーネントのバッジ（CONTRIBUTING の一覧の名前。core の部品は `core/検査` のように）・内容の 1 行
  - 選択肢は 1 つずつチェックボックスにする（1 行に「/」で並べない）。おすすめを先頭にして「おすすめ」のバッジを付ける
  - 根拠・再現・リンクは `<details>` に入れる。3・4 の項目は選択肢を「済んだ」「このままでよい / 直してほしい」などにし、「決めてほしい」は書かない
  - 5 は 1 行ずつ（選んだもの・チケット・PR を添える）。コピーの対象にしない
- コピー（docs のフィードバックモードの「Markdown をコピー」と同じ考え方）: 各項目の「コピー」はその項目を選択肢ごと（`- [x]` / `- [ ]`）、
  下の「選んだものをまとめてコピー」は選んだ・一言を書いた項目だけを Markdown にしてクリップボードへ。利用者はそれをチャットに貼って返す。
  クリップボードが使えない環境（埋め込みなど）では、欄に出して手でコピーしてもらう
- **過去の判断（decisions/）と同じものは載せない。**載せるのは、前提が変わった「見直し候補」だけ（「2. 判断してほしい」に、
  前の判断の日付・回・理由を `<details>` に添えて）
- 各項目の `data-id` は項目ごとに一意にし、更新しても変えない（選んだ状態がブラウザに残っていて、それと結び付く）。選択肢の `data-opt` も同じ
- 末尾に「いま走っているもの・待っているもの」を1行
- 利用者の回答はチャットで受ける（貼られた Markdown の `- id:` で項目を引く。HTML に残った状態はエージェントは読まない）

## index.html — 結果をひとまとめにしたもの

7 の報告の直前に作る（チェックの途中で作り直してもよい）。チェックリストより先に開かれる前提で、first view で全体が分かるようにする。

- 雛形: [templates/index.html](../templates/index.html)。TODO.html と同じ見た目
- 冒頭: 版・対象のコミット・日時、結果のバッジ（✅ / ⚠️）、リリースノートの概要（7 の報告と同じ 3 文）、TODO.html へのリンクと件数
- 手順ごとのカード（1〜6・8・9-1・9-2・10-1・10-2・10-5・11・13）: 結果の1行（例: 「13 / 13」「要検討 0 件」「priority 7 以上 0 件」）、
  状態の色、成果物へのリンク（`visibility-check.md`・`docs-vs-impl.md`・`site-crawl.md`・`docs-rules.md`・`ci-checks.md`・
  `ide-plugin-nightly.md`・`ide-plugin-e2e.md`・`ide-plugin-android-studio.md`・`install-kit.md`・`install-e2e.md`・`exploratory-<コンポーネント>.md`・`screenshots/`）。詳細は `<details>`
- 重要な警告（priority 7 以上）: タイトルと1〜2文。TODO.html の該当項目と同じ内容
- 軽微な警告: 件数と、手順ごとの内訳だけ（本文は各成果物へ）
- 過去の判断どおりで出さなかったもの: 手順ごとの件数と、この回で decisions/ に書き足した件数
- 数字や件数はチェックリストと同じものを使う（2箇所で数え直さない。チェックリストが SSoT）
