KATACHI-101.kts のスタンドアロン実行

katachi を試すだけでも Gradle plugin とテストモジュールの用意が要る。1 つの .kts に定義と assert() を書いて、コマンド 1 つで回したい

今
1. settings.gradle.kts に :architecture-test を足す2. build.gradle.kts に plugin と依存を書く3. src/test/kotlin/.../ArchitectureSpec.kt に定義と assert()4. ./gradlew :architecture-test:test// 「既存プロジェクトに合うか 5 分で試す」には重い
案
// architecture.katachi.ktsval architecture = architecture { "Screen".role { ... } }architecture.assert() $ katachi check architecture.katachi.kts   // brew の CLI に入口を足す// 2026-10-17: v0.3 ではやらない。K2 の内部エラー（@file:Import）で試行が止まった
リスク・デメリット
  • 利用者Gradle 版と .kts 版で同じ定義を二重に持ちたくなる。どちらが正かが曖昧になる
  • 利用者Kotlin スクリプトの初回コンパイルは遅く、依存の解決（@file:DependsOn）でネットワークが要る
  • ライブラリKotlin スクリプトの不具合（K2 の @file:Import の internal error）に左右される。CLI と Gradle の結果を一致させるテストが要る
