KATACHI-83SARIF の properties で「対象はファイル」を伝える

konsist { } がファイル自体を拒んだとき、IDE は SARIF の位置からファイル単位の違反だと分からず、注釈の位置を推測で決めている

今
// konsist { } の検査: このファイルは置いてはいけないSARIF: { "region": { "startLine": 1 } }// IDE は「1 行目の違反」なのか「ファイル全体の違反」なのか区別できない// AnnotationRanges.kt:32 の TODO として残っている
案（F-13、v0.4 の候補だった）
SARIF: {  "region": { "startLine": 1 },  "properties": { "katachi/target": "file" }}// IDE はファイル名のタブ・プロジェクトツリーに印を付ける
リスク・デメリット
  • 利用者ほぼ無い。注釈の位置が変わるだけ
  • ライブラリSARIF の properties は katachi 独自の約束になる。IDE と katachi の版がずれると古い IDE は無視する（害は無い）。golden の SARIF を更新
