KATACHI-103-Dkatachi.projectRoot で検査するツリーを指定する

「この規則を 3 か月前のコードに当てたら違反はいくつあったか」を見たくても、検査するツリーはテストを回したリポジトリに固定されている

今
$ git worktree add /tmp/old v0.2.0$ ./gradlew :architecture-test:test// 検査されるのは今のツリー。ルートは findProjectRoot のマーカー探索で決まる// 古いツリーで回すには、古いツリー側に今の定義を持ち込む必要がある
案（next-draft #19）
$ ./gradlew :architecture-test:test -Dkatachi.projectRoot=/tmp/old// 定義は今のもの、検査するツリーは指定したもの// 一部の動機は差分レポート（katachiDiff, KATACHI-223）が別の形で拾っている
リスク・デメリット
  • 利用者指定したツリーに git が無い・別のリポジトリだと gitTracked() の結果が変わる。指定し忘れや打ち間違いで「違反 0 件」と出ると気づきにくい
  • ライブラリルートを決める経路が 2 つになる。Gradle の入力に入れないと up-to-date 判定で古い結果が返る。IDE の定義 JSON の位置とのずれ
