## 何をするもの？

アーキテクチャのドキュメントは腐ります。「UseCase はここに置く」と書いた README は、
半年後には実態と食い違っています。テストとドキュメントが別々に書かれる限り、
どちらかが必ず嘘をつきます。

katachi は**同じ定義から両方を出します**。

```kotlin
val projectArchitecture = architecture {
    "domain".group {
        "UseCase" {
            title = "ユースケース"
            summary = "各画面で発生するアプリ固有の1つの振る舞い"
            example("GetUserUseCase", "ユーザーを取得する")

            layout {
                ":core:domain".module {
                    mainSourceSet / kotlin / modulePackage / "useCase" / "*UseCase".ktFile()
                }
            }
        }
    }
}
```

この1つの定義が、テストとしては「宣言に載っていないファイルがあれば落ちる」検査になり、
ドキュメントとしては「UseCase は何で、どこに置くのか」のページになります。
