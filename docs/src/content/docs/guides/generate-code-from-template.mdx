Add `.template { }` to a layout declaration and that file can be generated as code.

```kt {7-8,26-27} nocollapse
val modulePackage = capitalizedModuleNamePackage("com.example")

"UseCase" {
    layout {
        ":core:domain".module {
            mainSourceSet / kotlin / modulePackage / "useCase" /
                "${capture("name")}UseCase".ktFile()
                    .template {
                        val name = captureValue("name")
                        """
                            package com.example.core.domain.useCase

                            interface ${name}UseCase {
                                suspend operator fun invoke()
                            }
                        """.trimIndent()
                    }
        }
    }
}

"UseCaseImplementation" {
    layout {
        ":core:domain".module {
            mainSourceSet / kotlin / modulePackage / "useCase" /
                "${capture("name")}UseCaseImpl".ktFile()
                    .template {
                        val name = captureValue("name")
                        val implBody by stringParameter(default = """TODO("Implement ${name}UseCase")""")
                        """
                            package com.example.core.domain.useCase

                            class ${name}UseCaseImpl : ${name}UseCase {
                                override suspend fun invoke() {
                                    $implBody
                                }
                            }
                        """.trimIndent()
                    }
        }
    }
}
```

```shell
# generate both UseCase and UseCaseImplementation at once
./gradlew katachiTemplate \
    --arg "template=UseCase,UseCaseImplementation" --arg "name=GetItemList"
```

`--arg template=<specifier>` says which templates to generate.

## Specifying a template — `--arg template=`

One template is specified as `group.role.id`. Leave off the group when there is none; `id` can be left out only when that role has just one template.

| What you write | What it means |
| --- | --- |
| `Controller` | The one template of role `Controller`, which is in no group |
| `feature.Screen` | The one template of role `Screen`, in group `feature` |
| `RepositoryInterface.settings` | A specifier with no group. Usable only when the role name `RepositoryInterface` is unique across the whole architecture |

A role can be selected by name alone only when it has one template. With two or more, the run fails, listing the specifiers you could write instead. An unknown specifier fails the same way, listing the specifiers that are available.

## Parameters

Declare the parameters a generation run can pass with `--arg`, inside the template's block.

```kt {4}
"${capture("name")}UseCaseImpl".ktFile()
    .template {
        val name = captureValue("name")
        val implBody by stringParameter(default = """TODO("Implement ${name}UseCase")""")

        // ...
    }
```

**The property's name is the parameter's name, as is.** `val implBody by stringParameter(default = ...)` declares the parameter passed as `--arg implBody=...`.

```shell
./gradlew katachiTemplate \
    --arg "template=UseCaseImplementation" \
    --arg "name=GetItemList" --arg 'implBody=println("Hello World")'
```

There are four parameter types. All of them are passed as `--arg name=value`.

| How to write it | How to pass it | What it accepts |
| --- | --- | --- |
| `val name by stringParameter()` | `--arg name=User` | Anything |
| `val withImpl by booleanParameter(default = true)` | `--arg withImpl=false` | `true` / `false` (lower case only) |
| `val pageSize by intParameter(default = 20)` | `--arg pageSize=50` | An integer |
| `val visibility by enumParameter(default = Visibility.Public)` | `--arg visibility=Internal` | An enum entry name |

**A capture and a parameter are each one, by name, across every template a single run generates.** If two templates share one `capture("name")`, one `--arg name=User` fills in both. A **type or a default** that disagrees between them is an error.

## When the destination has a wildcard, name it and pass a value

`capture()` gives a `*` a name. It doesn't declare anything by itself — it just returns a string with the name embedded in it — so you can write it right inside a Kotlin string template.

```kt {2}
layout {
    "feature" / capture("feature") / "src" / "main" / "kotlin" / "*ViewModel".ktFile()
}
```

**As far as checking goes, it's exactly the same as `*`.** Rewriting `capture("feature")` as `"*"` doesn't change which files are allowed, not even one.

The name is used when passing a value with `--arg`. Left as `*`, a template can't tell whether to generate into `feature/home` or `feature/settings`. Name it, and you can choose with `--arg feature=home`. For a Role with no template, `*` on its own is fine.

`.template { }` is attached to the file declaration itself, so the destination path is fixed to that one `layout { }` declaration. If a `*` or `**` with no name from `capture()` is still left in it, there is nowhere for a value to arrive, so **it fails as soon as `.template { }` is attached**.

```kt {3,5-8} nocollapse
"FeatureComponent" {
    layout {
        ":feature:${capture("feature")}".module {
            "commonMain".sourceSet / kotlin / modulePackage / "component" /
                "${wildcard("feature").pascalCase}${capture("name")}".ktFile()
                    .template {
                        val feature = captureValue("feature")
                        val name = captureValue("name")
                        val component = "${feature.pascalCase}$name"

                        """
                            package com.example.kmp.feature.$feature.component

                            @Composable
                            internal fun $component(title: String) {
                                Text(text = title)
                            }
                        """.trimIndent()
                    }
        }
    }
}
```

```shell
./gradlew katachiTemplate \
    --arg "template=FeatureComponent" --arg "feature=home" --arg "name=UserCard"
```

`--arg feature=home` decides the `*` of `:feature:${capture("feature")}` as `home`, so `HomeUserCard.kt` lands in `:feature:home`'s `component/`.

**A capture's name becomes the `--arg` argument name, as is.** Inside the template, read the same value with `captureValue("feature")`.

### Rules for naming

- **It can't be used on `**`.** How many levels of directory to create isn't decided
- A name follows the same rule as a Role name (starts with a letter, followed by letters, digits, `_`, `-`)

## When a file already exists

`--arg onExisting=` chooses what happens when a file already exists at the destination. **The default is `fail`.** When generating more than one template at once, `onExisting` applies to the whole set.

| Value | Behavior |
| --- | --- |
| `fail` (default) | If even one already exists, **writes none** and fails |
| `skip` | If even one already exists, **writes none**, without failing either |
| `overwrite` | Replaces what's there |

```shell
./gradlew katachiTemplate \
    --arg "template=UseCase" --arg "name=GetItemList" --arg "onExisting=overwrite"
```

You can also set the default in build.gradle.kts.

```kts {6} title="architecture-test/build.gradle.kts"
import me.tbsten.katachi.gradle.KatachiOnExisting

katachi {
    processors {
        template {
            onExisting = KatachiOnExisting.SKIP
        }
    }
}
```

## Listing templates and seeing their details

The **`katachiTemplates` task** shows which templates exist, and what to pass to generate what.

```shell
# a list of templates (title / summary, parameter names, the specifier you can write for --arg template=)
./gradlew katachiTemplates

# the detail of one template
./gradlew katachiTemplates --arg "template=data.RepositoryInterface.user"
```

The detail shows the list of parameters, the destination path and the file's contents, and a `katachiTemplate` command.

```
  [templates] Previewed with: item=${item} (placeholder)
  [templates] File (path relative to the project root):
  [templates]   data/src/commonMain/kotlin/com/example/kmp/data/user/${name}Repository.kt
  [templates]     | interface ${name}Repository {
  ...
```

## Summary

- Add **`.template { }`** to a file declaration, and the **`katachiTemplate` task** can generate that file as code.
- The **`katachiTemplates` task** shows a list of templates, and the detail of each parameter and destination path.
