アーキテクチャ定義に `template { }` を追加すると、その定義からコードを生成できます。

```kt {14} nocollapse
val modulePackage = capitalizedModuleNamePackage("com.example")

"UseCase" {
    layout {
        ":core:domain".module {
            mainSourceSet / kotlin / modulePackage / "useCase" / "*UseCase".ktFile()
            mainSourceSet / kotlin / modulePackage / "useCase" / "*UseCaseImpl".ktFile()
        }
    }

    useCaseTemplate()
}

private fun RoleScope.useCaseTemplate() = template {
    // テンプレートに使用する引数を定義できます
    val name by stringParameter()
    val implBody by stringParameter(default = """TODO("${name}UseCase の実装")""")

    // file() で、この template が生成するファイルを1つ宣言します
    file("${name}UseCase.kt") {
        """
            package com.example.core.domain.useCase

            interface ${name}UseCase {
                suspend operator fun invoke()
            }
        """.trimIndent()
    }

    file("${name}UseCaseImpl.kt") {
        """
            package com.example.core.domain.useCase

            class ${name}UseCaseImpl : ${name}UseCase {
                override suspend fun invoke() {
                    $implBody
                }
            }
        """.trimIndent()
    }
}
```

```shell
# テンプレート生成を実行する
./gradlew katachiTemplate \
    --arg "roleName=UseCase" --arg "name=GetItemList"
```

`--arg roleName="<Roleの名前>"` と 各テンプレートに設定された引数を設定して呼び出す必要があります。

## パラメータ

コード生成時に `--arg` で渡せるパラメータを定義できます。

```kt
template {
    val name by stringParameter()
    val implBody by stringParameter(default = """TODO("${name}UseCase の実装")""")

    // ...
}
```

**プロパティの名前がそのままパラメータの名前になります。** `val name by stringParameter()` は `--arg name=...` で渡すパラメータを宣言します。

`default` 引数にデフォルト値を設定することで引数が設定されなかった際のデフォルト値を設定できます。

```shell
./gradlew katachiTemplate \
    --arg "roleName=UseCase" \
    --arg "name=GetItemList" --arg 'implBody=println("Hello World")'
```

パラメータの型は4つです。どれも `--arg 名前=値` で渡します。

| 書き方 | 渡し方 | 受け付ける値 |
| --- | --- | --- |
| `val name by stringParameter()` | `--arg name=User` | 何でも |
| `val withImpl by booleanParameter(default = true)` | `--arg withImpl=false` | `true` / `false`（小文字のみ） |
| `val pageSize by intParameter(default = 20)` | `--arg pageSize=50` | 整数 |
| `val visibility by enumParameter(default = Visibility.Public)` | `--arg visibility=Internal` | enum のエントリ名 |

default の無い enum パラメータは `val visibility by enumParameter(Visibility.entries)` と書きます。

## 生成先にワイルドカードがあるときは、名前を付けて値を渡す

テンプレートが言うのはファイル名だけで、ディレクトリは `layout { }` が決めます。では `layout { }` に `:feature:*` のようなワイルドカードがあるとき、どのモジュールに作るのか。**そのワイルドカードに [`capture()`](/katachi/ja/guides/layout/#ワイルドカードに名前を付ける) で名前を付け、`--arg` で値を渡します。**

```kt {3,9} nocollapse
"FeatureComponent" {
    layout {
        ":feature:*".module(capture = "feature") {
            "commonMain".sourceSet / kotlin / modulePackage / "component" /
                "${wildcard("feature").pascalCase}*".ktFile()
        }
    }
    template {
        val feature = captureValue("feature")
        val name by stringParameter()
        val component = "${feature.pascalCase}$name"

        file("$component.kt") {
            """
                package com.example.kmp.feature.$feature.component

                @Composable
                internal fun $component(title: String) {
                    Text(text = title)
                }
            """.trimIndent()
        }
    }
}
```

```shell
./gradlew katachiTemplate \
    --arg "roleName=FeatureComponent" --arg "feature=home" --arg "name=UserCard"
```

`--arg feature=home` が `:feature:*` の `*` を `home` に決めるので、`HomeUserCard.kt` は `:feature:home` の `component/` に入ります。

**capture の名前は、そのまま `--arg` の名前になります。** テンプレートの中では、同じ値を `captureValue("feature")` で読めます。上の例ではパッケージ名とファイル名に使っています。`by stringParameter()` で宣言し直す必要はありません。宣言すると同じ名前を2か所から受け取ることになり、`katachiTemplate` / `katachiTemplates --arg roleName=...` を実行した時点でエラーになります（`./gradlew test` の検査はテンプレートを走らせないので、そこでは見つかりません）。`if (withTest) { }` のような分岐の中だけで宣言したパラメータも、その分岐を通らない実行で見つかります。`roleName` と `onExisting` も、同じ理由で capture の名前には使えません。

ディレクトリの `capture()` も同じ使い方です。

```kt
layout {
    ":".module {
        mainSourceSet / kotlin / modulePackage / "controller" / capture("resource") / "*Controller".ktFile()
    }
}
```

`--arg resource=user --arg name=User` で `controller/user/UserController.kt` ができます。`controller/user/` がまだ無ければ作ります。

<Aside>
**モジュールの capture に渡せるのは、実在するモジュールだけです。** `:feature:*` は「今あるモジュール」を指す宣言なので、無いモジュールに書いたファイルは次の検査で違反になります。先に `settings.gradle.kts` にモジュールを足してください。ディレクトリの capture にはこの制約はありません。
</Aside>

### 生成先がちょうど1つに決まるときだけ書く

katachi は Role の `layout { }` の各パスについて、capture を `--arg` の値で埋めます。そのうえで、ディレクトリにワイルドカードが残らず、ファイル名がファイルのパターンに合うパスを生成先の候補にします。**候補がちょうど1つのときだけ書き込みます。**

| 状況 | どうなるか |
| --- | --- |
| capture の値を渡していない | 足りない `--arg` を名指しして失敗します |
| 候補が2つ以上ある | 候補のパスを並べて失敗します。katachi はどれかを勝手に選びません |
| ディレクトリに名前の無い `*` が残る | そのパスは候補になりません。どのパスもそうなら、`capture()` で名前を付けるよう案内して失敗します |
| 値が1つのディレクトリ名にならない | 空・`.`・`..`・`/` や `\` を含む値、ファイル名に使えない文字を含む値は失敗します |
| モジュールが無い | 今あるモジュールと、それぞれを選ぶ `--arg` を並べて失敗します。ほかのパスがファイルを受け取れても書き込みません |

ディレクトリの部分一致（`feature-*`）と `**` には名前を付けられません。生成先がそういうパスしか無い Role は、テンプレートで生成できません。モジュールキーの `*` は、`":feature:*-impl".module(capture = "feature")` のような部分一致でも名前を付けられます（値は `*` の部分、`--arg feature=home` で `:feature:home-impl`）。

## 既にファイルがあるとき

生成先に既にファイルがある場合の振る舞いは `--arg onExisting=` で選べます。**既定は `fail` です。**

| 値 | 振る舞い |
| --- | --- |
| `fail` (既定) | 1つでも既にあれば**1つも書かずに**失敗します |
| `skip` | 1つでも既にあれば**1つも書かず**、失敗もしません |
| `overwrite` | 既存を置き換えます |

```shell
./gradlew katachiTemplate \
    --arg "roleName=UseCase" --arg "name=GetItemList" --arg "onExisting=overwrite"
```

既定値は build.gradle.kts で設定することもできます。

```kts title="architecture-test/build.gradle.kts"
import me.tbsten.katachi.gradle.KatachiOnExisting

katachi {
    processors {
        template {
            onExisting = KatachiOnExisting.SKIP
        }
    }
}
```

## テンプレートの一覧と詳細を見る

どの役割がテンプレートを持ち、何を渡せば何が生成されるかは **`katachiTemplates` task** で確かめられます。

```shell
# テンプレートを持つ役割の一覧（title / summary、パラメータ名、生成するファイルの数）
./gradlew katachiTemplates

# 1つの役割のテンプレートの詳細
./gradlew katachiTemplates --arg "roleName=Repository"
```

詳細には、パラメータの一覧（型・既定値・受け付ける値・必須かどうか）、生成先のパスとファイルの中身、そのまま貼れる `katachiTemplate` のコマンドが出ます。

```
  [templates] Previewed with: name=${name} (placeholder), item=${item} (placeholder), withImpl=true (default)
  [templates] Files (paths relative to the project root):
  [templates]   data/src/commonMain/kotlin/com/example/kmp/data/user/${name}Repository.kt
  [templates]     | interface ${name}Repository {
  ...
  [templates] Other values change which files are produced:
  [templates]   --arg withImpl=false: leaves out ${name}RepositoryImpl.kt
```

生成先にワイルドカードの名前がある Role では、`Captures` の節も出ます。どの `--arg` がどのディレクトリを選ぶかが分かります。

```
  [templates] Captures (--arg values that choose the directory):
  [templates]   resource: level 7 of src/main/kotlin/com/example/controller/*/*Controller.kt
  ...
  [templates] Generate it with:
  [templates]   ./gradlew katachiTemplate --arg roleName=api/Controller --arg resource=resource --arg name=Name
```

## まとめ

- **`template { }`** をアーキテクチャ定義に追加すると、**`katachiTemplate` task** でテンプレートからコードを生成できます。
- **`katachiTemplates` task** で、テンプレートの一覧と、パラメータ・生成されるファイルの詳細を確かめられます。
- **生成先は `layout { }` が決めます。** テンプレートはファイル名だけを言うので、配置の定義と生成が食い違うことはありません。
- 生成先に **ワイルドカードがあるときは、`capture()` で名前を付けて `--arg` で値を渡します。** 生成先がちょうど1つに決まらなければ、何も書かずに失敗します。
