アーキテクチャ定義に `template { }` を追加すると、その定義からコードを生成できます。

```kt {14} nocollapse
val modulePackage = capitalizedModuleNamePackage("com.example")

"UseCase" {
    layout {
        ":core:domain".module {
            mainSourceSet / kotlin / modulePackage / "useCase" / "*UseCase".ktFile()
            mainSourceSet / kotlin / modulePackage / "useCase" / "*UseCaseImpl".ktFile()
        }
    }

    useCaseTemplate()
}

private fun RoleScope.useCaseTemplate() = template {
    // テンプレートに使用する引数を定義できます
    val name by stringParameter()
    val implBody by stringParameter(default = """TODO("${name}UseCase の実装")""")

    // file() で、この template が生成するファイルを1つ宣言します
    file("${name}UseCase.kt") {
        """
            package com.example.core.domain.useCase

            interface ${name}UseCase {
                suspend operator fun invoke()
            }
        """.trimIndent()
    }

    file("${name}UseCaseImpl.kt") {
        """
            package com.example.core.domain.useCase

            class ${name}UseCaseImpl : ${name}UseCase {
                override suspend fun invoke() {
                    $implBody
                }
            }
        """.trimIndent()
    }
}
```

```shell
# テンプレート生成を実行する
./gradlew katachiTemplate \
    --arg "roleName=UseCase" --arg "name=GetItemList"
```

`--arg roleName="<Roleの名前>"` と 各テンプレートに設定された引数を設定して呼び出す必要があります。

## パラメータ

コード生成時に `--arg` で渡せるパラメータを定義できます。

```kt
template {
    val name by stringParameter()
    val implBody by stringParameter(default = """TODO("${name}UseCase の実装")""")

    // ...
}
```

**プロパティの名前がそのままパラメータの名前になります。** `val name by stringParameter()` は `--arg name=...` で渡すパラメータを宣言します。

`default` 引数にデフォルト値を設定することで引数が設定されなかった際のデフォルト値を設定できます。

```shell
./gradlew katachiTemplate \
    --arg "roleName=UseCase" \
    --arg "name=GetItemList" --arg 'implBody=println("Hello World")'
```

パラメータの型は4つです。どれも `--arg 名前=値` で渡します。

| 書き方 | 渡し方 | 受け付ける値 |
| --- | --- | --- |
| `val name by stringParameter()` | `--arg name=User` | 何でも |
| `val withImpl by booleanParameter(default = true)` | `--arg withImpl=false` | `true` / `false`（小文字のみ） |
| `val pageSize by intParameter(default = 20)` | `--arg pageSize=50` | 整数 |
| `val visibility by enumParameter(default = Visibility.Public)` | `--arg visibility=Internal` | enum のエントリ名 |

default の無い enum パラメータは `val visibility by enumParameter(Visibility.entries)` と書きます。

## 既にファイルがあるとき

生成先に既にファイルがある場合の振る舞いは `--arg onExisting=` で選べます。**既定は `fail` です。**

| 値 | 振る舞い |
| --- | --- |
| `fail` (既定) | 1つでも既にあれば**1つも書かずに**失敗します |
| `skip` | 1つでも既にあれば**1つも書かず**、失敗もしません |
| `overwrite` | 既存を置き換えます |

```shell
./gradlew katachiTemplate \
    --arg "roleName=UseCase" --arg "name=GetItemList" --arg "onExisting=overwrite"
```

既定値は build.gradle.kts で設定することもできます。

```kts title="architecture-test/build.gradle.kts"
import me.tbsten.katachi.gradle.KatachiOnExisting

katachi {
    processors {
        template {
            onExisting = KatachiOnExisting.SKIP
        }
    }
}
```

## テンプレートの一覧と詳細を見る

どの役割がテンプレートを持ち、何を渡せば何が生成されるかは **`katachiTemplates` task** で確かめられます。

```shell
# テンプレートを持つ役割の一覧（title / summary、パラメータ名、生成するファイルの数）
./gradlew katachiTemplates

# 1つの役割のテンプレートの詳細
./gradlew katachiTemplates --arg "roleName=Repository"
```

詳細には、パラメータの一覧（型・既定値・受け付ける値・必須かどうか）、生成先のパスとファイルの中身、そのまま貼れる `katachiTemplate` のコマンドが出ます。

```
  [templates] Previewed with: name=${name} (placeholder), item=${item} (placeholder), withImpl=true (default)
  [templates] Files (paths relative to the project root):
  [templates]   data/src/commonMain/kotlin/com/example/kmp/data/user/${name}Repository.kt
  [templates]     | interface ${name}Repository {
  ...
  [templates] Other values change which files are produced:
  [templates]   --arg withImpl=false: leaves out ${name}RepositoryImpl.kt
```

## まとめ

- **`template { }`** をアーキテクチャ定義に追加すると、**`katachiTemplate` task** でテンプレートからコードを生成できます。
- **`katachiTemplates` task** で、テンプレートの一覧と、パラメータ・生成されるファイルの詳細を確かめられます。
- **生成先は `layout { }` が決めます。** テンプレートはファイル名だけを言うので、配置の定義と生成が食い違うことはありません。
