`ktFileContent { }` を使うと、Role の Kotlin ファイルに何を置いてよいかを、`layout { }` と同じ許可リスト（allow list）で定義できます。

例えば「このファイルには ViewModel というクラスのみを配置できる」といったルールを指定することができます。

```kt nocollapse {6,8-13,15-19}
"ViewModel".role {
  layout {
    "feature" / capture("feature") / mainSourceSet / kotlin / "**" / "*ViewModel".ktFile()
  }
  ktFileContent {
    `package`("com.example.feature.**")

    `import`("kotlin.**")
    `import`("kotlinx.coroutines.**")
    `import`("androidx.**")
    `import`("dagger.hilt.**")             // @HiltViewModel
    `import`("javax.inject.**")            // @Inject
    `import`("com.example.domain.**")

    required(annotated("HiltViewModel"), public, `class`, fileName).superclass("ViewModel") {
      required(public, `val`, "uiState").type("StateFlow<${fileName.replace("ViewModel", "UiState")}>")
      allow(public, `fun`, "on*")().returns("Unit")
      allow(private, anythingElse)
    }
  }
}
```

## インストール

`ktFileContent { }` は別モジュール `me.tbsten.katachi:katachi-konsist` に入っています。`build.gradle.kts` の依存に追加してください。

```kts title="build.gradle.kts" {2}
dependencies {
  testImplementation("me.tbsten.katachi:katachi-konsist:<version>")
}
```

次に、`projectArchitecture.assert()` に `FileConstraintCheck()` を渡すと、`ktFileContent { }` の検査を実行できます。

```kt del={3} ins={4}
@Test
fun `アーキテクチャに沿ったファイル配置になっている`() {
  projectArchitecture.assert()
  projectArchitecture.assert(FileConstraintCheck())
}
```

## import, package の宣言

`ktFileContent { }` を書いただけでは package, import 宣言を含む全ての宣言が禁止されます。(これは katachi が Deny by default の原則に従うためです。)

まずはファイル内で利用できる package, import 宣言を定義してみましょう。

```kt {7,9}
"ViewModel".role {
  layout {
    "feature" / capture("feature") / mainSourceSet / kotlin / "**" / "*ViewModel".ktFile()
  }

  ktFileContent {
    `package`("com.example.feature.${captureValue("feature")}.**")

    `import`("kotlin.**")
  }
}
```

このあとのセクションの例では `package` / `import` の行を省き、`// package / import の行は省略` とだけ書きます。写すときは、ファイルに合わせた `` `package`(…) `` / `` `import`(…) `` の行を書き足してください。

## class, interface, object 宣言を許可する

そのファイル内に class, interface, object の配置を許可する場合、`required(...)` または `allow(...)` に、許可したい宣言の種類と名前を渡します。

- `required(...)` で指定した宣言は必ず存在する必要があります。
- `allow(...)` で指定した宣言は存在を許されます。存在しない場合も違反にはなりません。

class, interface, object の行に `{ }` を書かないと、その宣言はメンバ（primary constructor のプロパティを含む）を1つも持てません。メンバを問わないときは `{ allow(anythingElse) }` を付けます。

<Tabs>
  <TabItem label="Android での例">

    ```kt {6, 15, 24} nocollapse
    "UseCase".role {
      layout { /* ... */ }

      ktFileContent {
        // package / import の行は省略
        required(`class`, "*UseCase") { allow(anythingElse) } // UseCase で終わる名前を持つ class
      }
    }

    "ViewModel".role {
      layout { /* ... */ }

      ktFileContent {
        // package / import の行は省略
        required(`class`, "*ViewModel") { allow(anythingElse) } // ViewModel で終わる名前を持つ class
      }
    }

    "NavigationRoute".role {
      layout { /* ... */ }

      ktFileContent {
        // package / import の行は省略
        required(data, `object`, "*Route") // Route で終わる名前を持つ data object
      }
    }
    ```

  </TabItem>

  <TabItem label="MVC での例">

    ```kt {6, 15, 24} nocollapse
    "Controller".role {
      layout { /* ... */ }

      ktFileContent {
        // package / import の行は省略
        required(`class`, fileName) { allow(anythingElse) } // ファイル名と同じ名前の Controller class が 1 つ必要
      }
    }

    "Service".role {
      layout { /* ... */ }

      ktFileContent {
        // package / import の行は省略
        required(`class`, fileName) { allow(anythingElse) } // ファイル名と同じ名前の Service class が 1 つ必要
      }
    }

    "Model".role {
      layout { /* ... */ }

      ktFileContent {
        // package / import の行は省略
        required(data, `class`, "*") { allow(anythingElse) } // Model は data class
      }
    }
    ```

  </TabItem>
</Tabs>

宣言に `data`, `internal` といった修飾子が必要な場合は修飾子も渡すことができます。

```kt
allow(public, `interface`, "*UseCase") { allow(anythingElse) } // UseCase interface は public である必要がある。
allow(internal, `class`, "*UseCaseImpl") { allow(anythingElse) } // UseCaseImpl class は internal である必要がある。
```

また `class`, `interface`, `object` のいずれでも良い場合は `type` を渡すこともできます。

```kt
allow(public, type, "*Repository") { allow(anythingElse) }
```

## プロパティ・関数の宣言を許可する

プロパティ・関数の宣言を許可したい場合は `val`/`var`, `fun` を種類として渡して定義します。

<Tabs>
  <TabItem label="Android での例">

    ```kt {6, 7} nocollapse
    "ScreenComposable".role {
      // ...

      ktFileContent {
        // package / import の行は省略
        allow(private, `val`, "*") // private 変数を許可する
        required(`fun`, "*Screen") // Screen で終わる名前を持つ関数が1つ以上必要

        required(`fun`, "doSomethingWithoutArg")() // 引数なしの doSomethingWithoutArg が必要
        required(`fun`, "doSomethingWithSingleArg")("action: *UiAction") // 引数が1つの doSomethingWithSingleArg が必要
        required(`fun`, "doSomethingWithAnyArgs")(anyArgs()) // 引数を問わない doSomethingWithAnyArgs が必要
      }
    }
    ```

    また 許可するプロパティ・関数は class などの中にも定義することができます。

    ```kt
    required(`class`, "*ViewModel") {
      required(`val`, "uiState").type("StateFlow<*>") // uiState: StateFlow<*> が必要
    }

    required(`class`, "*UseCase") {
      required(suspend.optional(), operator, `fun`, "invoke")(anyArgs()) // operator fun invoke が必要。suspend は付いていても無くてもよい
      allow(private, anythingElse) // コンストラクタで受け取る Repository など
    }
    ```

  </TabItem>

  <TabItem label="MVC での例">

    ```kt {6-8, 18-20} nocollapse
    "Controller".role {
      // ...

      ktFileContent {
        // package / import の行は省略
        required(`class`, fileName) {
          allow(private, `val`, "*").type("*Service") // 呼び出す Service を private val で持つ
          allow(`fun`, "*")(anyArgs())            // ハンドラの関数。名前も引数も問わない
        }
      }
    }

    "Service".role {
      // ...

      ktFileContent {
        // package / import の行は省略
        required(`class`, fileName) {
          allow(private, `val`, "*").type("*Repository") // 呼び出す Repository を private val で持つ
          allow(`fun`, "*")(anyArgs())
        }
      }
    }
    ```

  </TabItem>
</Tabs>

## typealias の宣言を許可する

typealias も他の宣言と同じように許可することができます。

```kt
allow(`typealias`, "*Handler")
```

## 宣言にアノテーションを指定させる

アノテーションを使いたいときは、`annotated()` を修飾子と同じように指定します。

<Tabs>
  <TabItem label="Android での例">

    ```kt {6} nocollapse
    "ViewModel".role {
      layout { /* ... */ }

      ktFileContent {
        // package / import の行は省略
        required(annotated("HiltViewModel"), public, `class`, fileName).superclass("ViewModel") {
          // ...
        }
      }
    }
    ```

  </TabItem>

  <TabItem label="MVC での例">

    ```kt {6, 17} nocollapse
    "Controller".role {
      layout { /* ... */ }

      ktFileContent {
        // package / import の行は省略
        required(annotated("RestController"), `class`, fileName) {
          // ...
        }
      }
    }

    "Service".role {
      layout { /* ... */ }

      ktFileContent {
        // package / import の行は省略
        required(annotated("Service"), `class`, fileName) {
          // ...
        }
      }
    }
    ```

  </TabItem>
</Tabs>

## まとめ

- `ktFileContent { }` は、Role の Kotlin ファイルに置いてよい宣言を、許可リストで定義します。
- 書かなかった宣言はすべて禁止されます。まず `package` と `import` を書きます。
- class・interface・object は `required(...)` と `allow(...)` に、種類と名前を渡して許可します。メンバを持たせるには `{ }` が要ります。
- プロパティ・関数は `val` / `var` / `fun`、typealias も同じ書き方です。アノテーションは `annotated()` で指定します。
- 検査には `katachi-konsist` を依存に足し、`assert(FileConstraintCheck())` を呼びます。
