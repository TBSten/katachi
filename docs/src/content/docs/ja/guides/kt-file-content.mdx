`ktFileContent { }` を使うと、Role の Kotlin ファイルに何を置いてよいかを、`layout { }` と同じ許可リスト（allow list）で定義できます。

例えば 「このファイルには ViewModel というクラスのみを配置できる」といったルールを指定することができます。

```kt nocollapse {6,8-13,15-19}
"ViewModel".role {
    layout {
        "feature" / capture("feature") / mainSourceSet / kotlin / "**" / "*ViewModel".ktFile()
    }
    ktFileContent {
        `package`("com.example.feature.**")

        `import`("kotlin.**")
        `import`("kotlinx.coroutines.**")
        `import`("androidx.**")
        `import`("dagger.hilt.**")             // @HiltViewModel
        `import`("javax.inject.**")            // @Inject
        `import`("com.example.domain.**")

        required(annotated("HiltViewModel"), public, `class`, fileName).superclass("ViewModel") {
            required(public, `val`, "uiState", "StateFlow<${fileName.replace("ViewModel", "UiState")}>")
            allow(public, `fun`, "on*")().returns("Unit")
            allow(private, anythingElse)
        }
    }
}
```

## インストール

`ktFileContent { }` は別アーティファクト `me.tbsten.katachi:katachi-konsist` に入っています。`build.gradle.kts` の依存に追加してください。

```kts title="build.gradle.kts" {2}
dependencies {
    testImplementation("me.tbsten.katachi:katachi-konsist:<version>")
}
```

次に、`projectArchitecture.assert()` に `FileConstraintCheck()` を渡すと、`ktFileContent { }` の検査を実行できます。

```kt del={3} ins={4}
@Test
fun `アーキテクチャに沿ったファイル配置になっている`() {
  projectArchitecture.assert()
  projectArchitecture.assert(FileConstraintCheck())
}
```

## import, package の宣言

`ktFileContent { }` を書いただけでは package, import 宣言を含む全ての宣言が禁止されます。(これは katachi が Deny by default の原則に従うためです。)

まずはファイル内で利用できる package, import 宣言を定義してみましょう。

```kt
"ViewModel".role {
    layout {
        "feature" / capture("feature") / mainSourceSet / kotlin / "**" / "*ViewModel".ktFile()
    }

    ktFileContent {
        `package`("com.example.feature.${captureValue("feature")}.**")

        `import`("kotlin.**")
    }
}
```

## class, interface, object 宣言を許可する

そのファイル内に class, interface, object の配置を許可する場合、`required(...)` または `allow(...)` に 宣言して良い宣言の種類と名前を渡して定義します。

- `required(...)` で指定した宣言は必ず存在する必要があります。
- `allow(...)` で指定した宣言は存在を許されます。存在しない場合も違反にはなりません。

<Tabs>
  <TabItem label="Android での例">

    ```kt {5, 13, 21} nocollapse
    "UseCase".role {
        layout { /* ... */ }

        ktFileContent {
            allow(`class`, "*UseCase") // UseCase で終わる名前を持つ class
        }
    }

    "ViewModel".role {
        layout { /* ... */ }

        ktFileContent {
            allow(`class`, "*ViewModel") // ViewModel で終わる名前を持つ class
        }
    }

    "Navigation Route".role {
        layout { /* ... */ }

        ktFileContent {
            allow(data, `object`, "*Route") // Route で終わる名前を持つ data object
        }
    }
    ```

  </TabItem>

  <TabItem label="MVC での例">

    ```kt {5, 13, 21} nocollapse
    "Controller".role {
        layout { /* ... */ }

        ktFileContent {
            required(`class`, fileName) // ファイル名と同じ名前の Controller class が必ず 1 つ
        }
    }

    "Service".role {
        layout { /* ... */ }

        ktFileContent {
            required(`class`, fileName) // ファイル名と同じ名前の Service class が必ず 1 つ
        }
    }

    "Model".role {
        layout { /* ... */ }

        ktFileContent {
            allow(data, `class`, "*") // Model は data class
        }
    }
    ```

  </TabItem>
</Tabs>

宣言に `data`, `internal` といった修飾子が必要な場合は修飾子も渡すことができます。

```kt
allow(public, `interface`, "*UseCase") // UseCase interface は public である必要がある。
allow(internal, `class`, "*UseCaseImpl") // UseCaseImpl class は internal である必要がある。
```

また `class`, `interface`, `object` のいずれでも良い場合は `type` を渡すこともできます。

```kt
allow(public, type, "*Repository")
```

## プロパティ・関数の宣言を許可する

プロパティ・関数の宣言を許可したい場合は `val`/`var`, `fun` を種類として渡して定義します。

<Tabs>
  <TabItem label="Android での例">

    ```kt {5, 6} nocollapse
    "ScreenComposable".role {
        // ...

        ktFileContent {
            allow(private, `val`, "*") // private 変数を許可する
            required(`fun`, "*Screen") // Screen で終わる名前を持つ関数が1つ以上ある

            required(`fun`, "doSomethingWithoutArg")() // 引数なしの doSomethingWithoutArg が必ずある
            required(`fun`, "doSomethingWithSingleArg")("action: *UiAction") // 引数が1つの doSomethingWithSingleArg が必ずある
            required(`fun`, "doSomethingWithAnyArgs")(anyArgs()) // 引数を問わない doSomethingWithAnyArgs が必ずある
        }
    }
    ```

    また 許可するプロパティ・関数は class などの中にも定義することができます。

    ```kt
    required(`class`, "*ViewModel") {
        required(`val`, "uiState", "StateFlow<*>") // uiState: StateFlow<*> が必ずある
    }

    required(`class`, "*UseCase") {
        required(suspend.optional(), operator, `fun`, "invoke")(anyArgs()) // operator fun invoke が必ずある。suspend は付いていても無くてもよい
        allow(private, anythingElse) // コンストラクタで受け取る Repository など
    }
    ```

  </TabItem>

  <TabItem label="MVC での例">

    ```kt {5-7, 16-18} nocollapse
    "Controller".role {
        // ...

        ktFileContent {
            required(`class`, fileName) {
                allow(private, `val`, "*", "*Service") // 呼び出す Service を private val で持つ
                allow(`fun`, "*")(anyArgs())            // ハンドラの関数。名前も引数も問わない
            }
        }
    }

    "Service".role {
        // ...

        ktFileContent {
            required(`class`, fileName) {
                allow(private, `val`, "*", "*Repository") // 呼び出す Repository を private val で持つ
                allow(`fun`, "*")(anyArgs())
            }
        }
    }
    ```

  </TabItem>
</Tabs>

## typealias の宣言を許可する

typealias も他の宣言と同じように許可することができます。

```kt
allow(`typealias`, "*Handler")
```

## 宣言にアノテーションを指定させる

アノテーションを使いたいときは、`annotated()` を modifier と同じように指定します。

<Tabs>
  <TabItem label="Android での例">

    ```kt {5} nocollapse
    "ViewModel".role {
        layout { /* ... */ }

        ktFileContent {
            required(annotated("HiltViewModel"), public, `class`, fileName).superclass("ViewModel") {
                // ...
            }
        }
    }
    ```

  </TabItem>

  <TabItem label="MVC での例">

    ```kt {5, 15} nocollapse
    "Controller".role {
        layout { /* ... */ }

        ktFileContent {
            required(annotated("RestController"), `class`, fileName) {
                // ...
            }
        }
    }

    "Service".role {
        layout { /* ... */ }

        ktFileContent {
            required(annotated("Service"), `class`, fileName)
        }
    }
    ```

  </TabItem>
</Tabs>
