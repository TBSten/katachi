katachi CLI (`katachi`) は、katachi の導入・運用を AI Agent に任せるために作られたコマンドラインツールです。

## インストール

katachi CLI は Homebrew でインストールできます。

```bash
brew install tbsten/tap/katachi
katachi --version
```

## コマンドリスト

| コマンド | 説明 |
|---| --- |
| [`doctor`](#doctor) | katachi が利用する環境が整っているか チェックする。 |
| [`scaffold`](#scaffold) | アーキテクチャテスト用のモジュール (`architecture-test`) を追加する。 |
| [`agent`](#agent) | AI Agent 向けのサブコマンド。  |

## doctor

katachi を利用するのに必要な環境が整っているかをチェックします。

```shell
katachi doctor
```

<details>
  <summary> 実行結果例 </summary>


具体的には以下をチェックします。

- [ ] Gradle が利用する JDK のバージョン
- [ ] プロジェクトの Kotlin のバージョン
- [ ] Git


## scaffold


デフォルトでは以下の構成で `:architecture-test` モジュールを作成します。

```
architecture-test/
├── build.gradle.kts
└── src/test/kotlin/com/example/app/test/architecture/
    ├── ProjectArchitecture.kt       # architecture { } を書く
    └── ProjectArchitectureTest.kt   # 定義どおりかを検査するテスト
```

### `scaffold --dry-run`

`--dry-run` オプションを指定すると、実際にはファイルを作成せずに、どのようなファイルが作成されるかを確認できます。

## agent

`agent` コマンドは AI Agent 向けのサブコマンド群です。

`agent` コマンドの詳細については `katachi agent --help` で確認してください。

## まとめ

- `katachi` は Homebrew で入れる、katachi と同じバージョンのコマンドラインツールです
- `doctor` で Gradle の JDK・Kotlin のバージョン・Git がそろっているかを確かめます
- `scaffold --package <package>` で検査用モジュール `:architecture-test` を作り、ビルドに組み込みます。`--dry-run` で先に中身を確かめられます
- `agent` の下のサブコマンドは AI Agent が導入の手順書に沿って使います
