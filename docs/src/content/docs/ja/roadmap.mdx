## 全体像

| バージョン | テーマ | 完了と言える条件 |
|---|---|---|
| **v0.1** | DSL + 検査 + `konsist { }` | 大規模なプロジェクトを表現でき、検査が通る |
| **v0.2** | Gradle plugin + ドキュメント生成 + テンプレート + baseline | `./gradlew katachiDocs` でドキュメントが出る。既存の違反を baseline に棚上げした状態で、新しい違反と、直したのに台帳に残っている項目でだけテストが落ちる |
| **v0.3 以降** | `declarations { }` / レポート出力 / 語彙数の計測 | **既存プロジェクト**に導入できる。v0.1 で書いた `konsist { }` の大半を `declarations { }` で置き換えられる |

## v0.2 — Gradle plugin・ドキュメント生成・テンプレート・baseline

katachi の売りが揃う段階で、**0.2.0 としてリリースしました**。Gradle plugin の足場と、その上で処理を走らせる仕組み（processor）、**ドキュメント生成**、テンプレートからのコード生成、baseline（実験的）が入っています。v0.2 の計画にあった `dependsOnlyOn` は 0.2.0 に間に合わず、下の v0.3 以降の表へ回しました。

```shell
./gradlew katachiDocs
```

プラグインを適用し、`katachi { architecture = "..." }` で定義を指せば、**テストと同じ定義から** Markdown を 2 軸で生成できます。

- **役割リファレンス** — この役割は何で、どこに置くか
- **ディレクトリ構成** — このディレクトリに何が置けるか

両方が同じモデルから導かれるので、**互いに矛盾しません。** 生成したあとのリンク切れも機械的に検査します。

出力の形は [ドキュメント生成](/katachi/ja/guides/document-generation/) に、走らせる仕組みは [ArchitectureProcessor とそのカスタマイズ](/katachi/ja/guides/processor/) に書いてあります。ドキュメント生成は processor の1つにすぎず、利用者が書いた処理も同じタスクから呼べます。

### そのほか v0.2 に入ったもの

| 機能 | 何ができるか |
|---|---|
| [`template { }`](/katachi/ja/guides/generate-code-from-template/) | 役割に適合するファイルをテンプレートから生成する。引数は型付きで受けられる（`stringParameter()` / `booleanParameter()` / `intParameter()` / `enumParameter()`）。`katachiTemplates` でテンプレートの一覧と詳細を確かめられる |
| [**baseline**](/katachi/ja/guides/baseline/)（実験的） | 既存の違反を台帳のファイルに記録し、**新しく増えた分だけ**で落とす。`architecture { baseline = baselineFile() }` と書き（`@OptIn(ExperimentalKatachiApi::class)` が要る）、台帳のファイル自身も `layout { }` で宣言する。`-Dkatachi.baseline.update=true` で記録、`-Dkatachi.baseline.prune=true` で直した分を台帳から消す |
| [`gradle()`](/katachi/ja/recipes/gradle/) | wrapper・settings・build スクリプト・`gradle.properties`・version catalog など、どのプロジェクトにもある Gradle のファイルを1行で宣言する |
| [ディレクトリの `konsist { }` の直下限定](/katachi/ja/guides/konsist-integration/#ディレクトリごとに制約をかける) | ディレクトリブロックに書いた `konsist { }` を、サブツリー全体ではなく直下のファイルだけに効かせる。`konsist(directOnly = true)` と書く。親と子で制約が違う構成（`util/` と `util/ksp/` など）に使う |
| IDE プラグイン（**未公開**） | IntelliJ IDEA / Android Studio のツールウィンドウからテンプレートを選び、引数を埋めてコードを生成する。katachi 本体の版とは別に進めていて、まだ公開していない |

## v0.3 以降 — 既存プロジェクトへの導入と `declarations { }`

既存プロジェクトに入れやすくするのが v0.3 以降の主題です。今ある違反を棚上げする baseline だけは、実験的な機能として v0.2 に先に入りました。

| 機能 | 何ができるか |
|---|---|
| **`dependsOnlyOn`** | 依存してよい先を**許可リスト**で書く。禁止リスト方式は書き漏れが素通りする。v0.2 の計画から移した |
| **レポート出力** | JSON / SARIF で出し、GitHub の PR にアノテーションとして載せる |
| **`pairedWith`** | 「すべての `Screen` に対応する `Preview` がある」のような網羅性を検査する |
| **語彙数の計測** | 役割の数と、役割ごとのファイル数を数値で出す |
| **Gradle のモデルに基づくモジュールの解決** | `projectDir` を変えたモジュールや、source set の実際の場所に追従する |

この段階の仕様はまだほとんど決まっていません。バージョン番号の割り当ても「v0.3 以降」とひとまとまりです。

### `declarations { }` — `konsist { }` からの昇格

v0.1 の `konsist { }` は、言ってしまえば**逃げ道**です。「`*UseCase` interface と `Default*UseCase` class だけを置く」のように、ほとんどの役割が言いたいことでも、毎回 Konsist の式で書き下すことになります。

```kt
"interface と Default 実装のみ".konsist {
    files.must { file ->
        val decls = file.declarations(includeNested = false, includeLocal = false)
        decls.size == 2 &&
            decls.any { it is KoInterfaceDeclaration && it.name.endsWith("UseCase") } &&
            decls.any { it is KoClassDeclaration && it.name.startsWith("Default") }
    }
}
```

同じ規則が、こう読めるようにしたい。

```kt
"UseCase" {
    declarations {
        `interface`("*UseCase")
        `class`("Default*UseCase")
    }
}
```

列挙していない top-level 宣言は書けません。2つめのクラスも、トップレベルの拡張関数も、置き忘れた `typealias` も。`layout { }` が配置の allow list であるのと同じ意味で、このブロックが中身の allow list になります。

katachi は「何が期待されていたか」を知っています。だから違反のときに、「制約が落ちた」以上のことを言えます。

```
[UnsatisfiedFileConstraint] core/domain/.../GetUserUseCase.kt
  The top-level declarations do not match what role UseCase allows.
  Expected: interface *UseCase, class Default*UseCase
  Actual:   interface GetUserUseCase, class GetUserUseCaseImpl, object Factory
  How to fix:
    - Rename GetUserUseCaseImpl to DefaultGetUserUseCase
    - Delete object Factory, or move it to another file
```

**上の形は素案で、確定ではありません。** 何を昇格させるかは、v0.1 を実プロジェクトで使って**溜まった `konsist { }` を見てから**決めます。材料を集める時間をとるため、v0.2 からこちらへ移しました。
