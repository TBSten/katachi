## <span id="katachi-home-problem">崩れるのは<br />いつも1ファイルから。</span>

置き場所の逸脱は、レビューで見逃しがちです。AI Agent が作ったファイルも、手本にするのは文書ではなく既存の配置。1つずれれば、そこから複製されていきます。

**ドキュメントには、強制力がない。**

</div>

<div class="katachi-home__tree" aria-label="検査されていないディレクトリ構造の例">

├─ useCase/
│  ├─ GetUserUseCase.kt
│  └─ UpdateUserUseCase.kt
├─ DeleteUserUseCase.kt  ← 置き場所が違う
└─ misc/
   └─ memo.md            ← 役割がない
```

<small>この2つを、誰も検査していない</small>

</div>

```

<small><span aria-hidden="true">●</span> 宣言済み　<span aria-hidden="true">●</span> 違反として報告される</small>

<div class="katachi-home__split-copy">

## <span id="katachi-home-solution">宣言した場所だけが<br />存在を許される</span>

katachi では、存在してよいものを宣言します。禁止を数え上げるのではありません。

**Deny by default — 宣言にないものは、存在できない。**

</div>

<div class="katachi-home__pillar-list">

<article class="katachi-home__pillar" data-katachi-pillar>

<p>03-01 — deny</p>

### 宣言にないファイルは<br />アーキテクチャ違反

禁止を数え上げる運用から、存在してよいものを宣言する運用へ。「いつの間にか増えた置き場所」が起きません。

```kt
"UseCase" { layout { "domain/useCase" / "*UseCase".ktFile() } }
// domain/useCase/Helper.kt → [UnexpectedFile]
```

</article>

<article class="katachi-home__pillar" data-katachi-pillar>

<p>03-02 — role</p>

### 役割駆動による<br />アーキテクチャ定義

1つの役割が2つのモジュールに住んでいても、説明は1箇所のまま。置き場所は `layout { }` を並べて宣言します。

```kt
"UseCase" {
  summary = "各画面で発生するアプリ固有の1つの振る舞い"
  layout { "core/domain/useCase" / "*UseCase".ktFile() }
  layout { "feature/home/useCase" / "*UseCase".ktFile() }
}
```

</article>

<article class="katachi-home__pillar" data-katachi-pillar>

<p>03-03 — docs</p>

### 検査した定義が、<br />そのままドキュメントへ

`title` / `summary` / `example` を役割の中に書きます。同じ定義からのドキュメント生成は v0.2 で予定しています。

```kt
"UseCase" {
  title = "ユースケース"
  summary = "各画面で発生するアプリ固有の1つの振る舞い"
  example("GetUserUseCase", "ユーザーを取得する")
}
```

</article>
