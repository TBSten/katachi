<div class="katachi-home__split-copy">

## <span id="katachi-home-problem">It always starts<br />with a single file.</span>

A file in the wrong place is easy to miss in review. And when an AI agent writes one, what it imitates is not your documentation — it is the placement already in the tree. One file off, and it gets copied from there.

**Documentation has no way to enforce itself.**

</div>

<div class="katachi-home__tree" aria-label="Example of a directory structure nobody checks">

<p>src/main/kotlin/com/example/</p>

```text
├─ useCase/
│  ├─ GetUserUseCase.kt
│  └─ UpdateUserUseCase.kt
├─ DeleteUserUseCase.kt  ← in the wrong place
└─ misc/
   └─ memo.md            ← has no role
```

<small>Nobody is checking these two</small>

</div>

</section>

<section class="katachi-home__split katachi-home__split--reverse" aria-labelledby="katachi-home-solution">

<div class="katachi-home__tree katachi-home__tree--allowed" aria-label="Example of a directory structure allowed by katachi">

<p>What ProjectArchitecture.kt allows</p>

```text
src/main/kotlin/com/example/
├─ useCase/*UseCase.kt       ✓ declared
├─ repository/*Repository.kt ✓ declared
├─ DeleteUserUseCase.kt      ✕ reported
└─ misc/memo.md              ✕ reported
```

<small><span aria-hidden="true">●</span> Declared&nbsp;&nbsp;<span aria-hidden="true">●</span> Reported as a violation</small>

</div>

<div class="katachi-home__split-copy">

## <span id="katachi-home-solution">Only what you declared<br />is allowed to exist</span>

In katachi you declare what may exist. You do not enumerate what is forbidden.

**Deny by default — anything not in the declaration cannot exist.**

</div>

</section>

<section class="katachi-home__pillars" aria-label="The three pillars of katachi" data-katachi-pillars data-active-pillar="0">

<div class="katachi-home__pillar-list">

<article class="katachi-home__pillar" data-katachi-pillar>

<p>03-01 — deny</p>

### A file you never declared<br />is an architecture violation

Stop enumerating what is forbidden; declare what may exist instead. Locations no longer appear out of nowhere.

```kt
"UseCase" { layout { "domain/useCase" / "*UseCase".ktFile() } }
// domain/useCase/Helper.kt → [UnexpectedFile]
```

</article>

<article class="katachi-home__pillar" data-katachi-pillar>

<p>03-02 — role</p>

### Architecture definitions<br />driven by roles

Even when one role lives in two modules, the explanation stays in one place. Declare its placements by listing `layout { }` blocks.

```kt
"UseCase" {
  summary = "A single app-specific behavior that occurs on a screen"
  layout { "core/domain/useCase" / "*UseCase".ktFile() }
  layout { "feature/home/useCase" / "*UseCase".ktFile() }
}
```

</article>

<article class="katachi-home__pillar" data-katachi-pillar>

<p>03-03 — docs</p>

### The definition you check<br />becomes the documentation

Write `title`, `summary`, and `example` inside the role. Generating documentation from that same definition is planned for v0.3.

```kt
"UseCase" {
  title = "Use case"
  summary = "A single app-specific behavior that occurs on a screen"
  example("GetUserUseCase", "Gets a user")
}
```

</article>

</div>
