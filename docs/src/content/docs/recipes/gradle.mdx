Build-related files don't belong to any layer of the app, yet there are a lot of them, and if you leave them alone they become regulars in `[UnexpectedFile]`. It's easiest to declare them together as a single group.

Since we don't want these to show up in the generated documentation, we add `documented = false`.

```kt collapse
// ProjectArchitecture.kt
import me.tbsten.katachi.dsl.architecture

val projectArchitecture = architecture {
    buildGroup()
}

// groups/BuildGroup.kt
import me.tbsten.katachi.dsl.DeclarationContainerScope

fun DeclarationContainerScope.buildGroup() = "build".group {
    documented = false
    title = "Build"

    gradle()
}

// roles/Gradle.kt
import me.tbsten.katachi.dsl.DeclarationContainerScope
import me.tbsten.katachi.dsl.gradle.*
import me.tbsten.katachi.dsl.kotlin.ktsFile

fun DeclarationContainerScope.gradle() = "Gradle" {
    title = "Gradle scripts"
    summary = "Build definitions and the Gradle wrapper"
    documented = false

    layout {
        ":".module {
            "settings.gradle".ktsFile()
            "gradle.properties".file()
            "gradlew".file()
            "gradlew.bat".file()
            "gradle" {
                "libs.versions.toml".file()
                "wrapper" {
                    "gradle-wrapper.jar".file()
                    "gradle-wrapper.properties".file()
                }
            }
        }

        ":architecture-test".module { }
    }
}
```

## What `.module { }` expands into

`":app".module { }` looks empty, but it's the same as the next two lines.

```kt
"app" {
    "build".ignore()
    "build.gradle".ktsFile()
}
```

**It never expands to more than that.** `src/` isn't included, so the contents of a module are declared by a separate Role. That's why a Role that only enumerates modules ends up with entirely empty blocks.

```kt
fun DeclarationContainerScope.gradleModule() = "GradleModule" {
    documented = false
    layout {
        ":app".module { }
        ":architecture-test".module { }
        ":feature:*".module { }
        ":data".module { }
        ":ui".module { }
        ":navigation".module { }
    }
}
```

List these one-to-one with the `include(...)` calls in `settings.gradle.kts`. Use wildcards like `:feature:*` **only for things that are expected to grow, like feature modules.** Writing fixed modules out one line at a time means you'll notice when one disappears.

## `documented = false` is not inherited

Writing it on the group doesn't propagate to the Roles inside it. **Write it in both places.**

```kt
fun DeclarationContainerScope.buildGroup() = "build".group {
    documented = false     // hide the group

    gradle()               // without writing it here too, the Role will show up
}
```

If you forget, `gradlew` and `gradle-wrapper.jar` will show up in the generated documentation's listing.

## Writing the root (`":"`)

`":"` is the root project, and it resolves to the project root itself. Files that **don't belong to any module**, like the wrapper or `settings.gradle.kts`, are written here.

```kt
":".module {
    "settings.gradle".ktsFile()
    "gradlew".file()
    // ...
}
```

<Aside type="caution">
Don't write `ignore()` or `anyFile()` inside `":".module { }`. Because the container is the same node as directly under `layout { }`, **it applies to the whole repository, not just the root module.**
</Aside>

## What fails when it disappears, and what doesn't

**Declarations without a wildcard**, like `gradle-wrapper.jar` or `libs.versions.toml`, fail with `[MissingFile]` when the actual file disappears. This lets you notice an accidental deletion.

On the other hand, **a declaration with a wildcard**, like `":feature:*".module { }`, **doesn't fail even with zero matches.** A pattern means "things matching this may exist," not "one must exist."

If you don't know about this asymmetry, you'll be confused by "I declared it, but it doesn't fail." **Write things you want to be guaranteed to exist with a fixed name.**

## What the build writes out

You don't need to declare `build/` or `.kotlin/`. If they're in `.gitignore`, the default `files = gitTracked()` won't even pass them to the check in the first place.

Even so, `.module { }` includes `"build".ignore()`, because a project that has switched to `files = wholeTree()` has no backing from git, and this way **the reasoning holds up under either setting.**

## In the samples

- `sample/jvm` — a single module. Everything is combined into one `Gradle`.
- `sample/android` / `sample/kmp` — multi-module. Split into `GradleModule` and `GradleRoot`.

<Aside>
The group name is `build`, but **the Kotlin package name is `gradle`.** This is because `build/` in `.gitignore` matches at every level, which would make the definition files themselves invisible to git. The group name and package name don't need to match.
</Aside>
