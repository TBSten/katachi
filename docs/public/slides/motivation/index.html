03 / 9

Konsist は「絞った範囲」しか見ない

Konsist.scopeFromProject()

.classes()

.withNameEndingWith("UseCase")

.assertTrue { ... }

Scope の外は検証されない

"UseCase" という名前を持つクラスだけが検証対象。宣言していないファイルやディレクトリは、そもそも視界に入らない。

プロジェクト全体を見て、「あるべきでないもの」を見つける手段が要る。

04 / 9

katachi の原則

Deny by default

宣言されていないファイルは、
存在を許されない。

05 / 9

2つだけ宣言する

"UseCase" {

title = "ユースケース"

summary = "各画面で発生する1つの振る舞い"

 

layout {

"src/.../useCase" / "*UseCase".ktFile()

}

}

Role — 現れて良いファイルの種類

名前 / 表示名 / 説明を1つの単位として持つ

layout — その配置場所

ディレクトリとファイル名パターンを宣言する

06 / 9

違反は、直し方ごと報告される

AI Agent が useCase/ の外に GetUserUseCase.kt を置いた場合

Katachi check failed: 1 violation (Unexpected: 1)

 

[UnexpectedFile] src/.../GetUserUseCase.kt

No role is defined for this file.

Nearby locations:

UseCase src/.../useCase/

How to fix:

- Move it to one of the locations above

- Delete it if it is not needed

- Add a new role for it: "GetUserUseCase" { ... }

事実・近い置き場所・修正方法までが1ブロック。人間にも AI Agent にも、そのまま読んで直せる形式。

# ユースケース

 

各画面で発生する1つの振る舞い

 

## 配置場所

| パス | 使い分け |

|---|---|

| .../useCase/*UseCase.kt | 複数の画面から使われるもの |

 

## 例

- GetUserUseCase ... ユーザーを取得する

title / summary / example / layout の description が、そのまま見出し・説明文・表になる。テストと同じ定義なので、片方だけが腐ることがない。

役割が違うので、併用する

katachi

プロジェクト全体の構造。
「どこに置くか」

Konsist

各ファイルの中身。
「どう書くか」

09 / 9

まとめ

AI 開発には、構造のルールを守らせる仕組みが要る

katachi は Deny by default でファイル配置をテストし、ドキュメントを生成する

中身の検証は Konsist に任せる — 役割分担
