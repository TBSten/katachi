KATACHI-72glob の実装課題 3 件

利用者に見えるのは「src//Foo.kt が src/*/Foo.kt に当たる」1 件。残り 2 件は glob を変えたときの回帰を見逃さないための内部整備

今
 1. GlobSpec が 1 ファイルで巨大（読み取り・変換・照合・文面が同居） 2. :katachi 側の PBT は GlobLexerSpec 中心。Glob 自体の性質テストが薄い3. "src/*/Foo.kt" に "src//Foo.kt" が当たる   // * が 0 文字になったので空の段を含むパスが当たる   // 実在のパスに空の段は無く、呼び出し元の約束に頼っている
案
1. 構文の読み取り / 変換 / 照合 / エラー文面で Spec を分ける2. 「パスを作ってから当てる」性質テストを :katachi に足す3. glob 側で空の段を弾く（例外にするか不一致にするかを決める）   // IDE・CLI など新しい呼び出し元が約束を知らなくても安全に
リスク・デメリット
  • 利用者機能の変化はほぼ無い。空の段を弾くと、裏口的に a//b と書いていた定義があればエラーになる（実例はほぼ無いと推測）
  • ライブラリSpec の分割は差分が大きくレビューしづらい。PBT は生成器の偏りで flaky になりうる
