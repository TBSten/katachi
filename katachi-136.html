KATACHI-136IDE プラグインのリリースサイクルを katachi 本体から分ける

IDE プラグインは katachi の Release に相乗りしているので、プラグインの遅れが本体のリリースを止め、プラグインだけの修正も本体のリリースを待つ

今
katachi の Release（published）  → publish.yml が buildPlugin  → katachi-intellij-plugin-<版>.zip を同じ Release に添付v0.3.0 では IDE プラグインの版の上げ忘れと E2E の遅れで本体が止まった
案（決めることは本文の 4 点）
intellij-v0.2.1 のような別のタグ・別の Release対応する katachi の版の範囲を plugin.xml とテストで示すchange-notes・prerelease skill の手順を本体から切り離す
リスク・デメリット
  • 利用者katachi とプラグインの版の組み合わせを利用者が意識する必要が出る。合わない組み合わせのときの表示（エラー文面）が要る
  • ライブラリRelease とタグが 2 系統になり、CHANGELOG・docs のバッジ・brew の CLI との並びを保守する。互換の範囲を CI で確かめる仕組みが要る
