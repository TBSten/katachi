KATACHI-88宣言の列挙からテンプレートを自動導出する

ktFileContent に「この Role のファイルには fileName の class がある」と書いているのに、.template { } の中身にも同じ class を手で書くので二重管理になる

今
"Screen".role {  layout { ... / "${capture("feature").pascalCase}Screen".ktFile()    .template(id = "feature.Screen") { """class ${name}Screen { }""" } }  // 生成  ktFileContent { required(`class`, fileName) }                         // 検査}// 検査を変えたらテンプレートも直す。忘れると生成直後に check が落ちる
案（形は未決）
"Screen".role {  layout { ... / "${capture("feature").pascalCase}Screen".ktFile()    .template(id = "feature.Screen") }   // 中身を書かない  ktFileContent { required(`class`, fileName) }}// → ktFileContent から「検査を通る最小形」class HomeScreen を導出// 中身を書いたテンプレートはそちらを優先
リスク・デメリット
  • 利用者導出される雛形は「検査を通る最小形」なので import・引数・アノテーションは結局手で足す。期待と違うと「余計なものを作られた」と感じる
  • 利用者ktFileContent の書き方が雛形の形にも波及する。検査のためだけの記述が生成にも影響する
  • ライブラリ宣言 → Kotlin コードの逆変換（型・修飾子・部分一致 *Screen の扱い）を実装する。ワイルドカードは一意に導出できないので「導出できない宣言」の決まりが要る
