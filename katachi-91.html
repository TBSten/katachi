KATACHI-91DSL の誤り検出・役割名補完・打鍵ごとの再評価

定義の DSL の誤り（テンプレートの名前の無い * など）は Gradle を回して失敗するまで分からない。IDE は打っている最中には何も言わない

今
"Screen".role { layout {  "feature" / "*" / ... / "*Screen".ktFile().template(id = "feature.Screen")} }// 名前の無い * はテンプレートの生成先が決まらず定義の誤り// 気づくのは Gradle を回したとき。注釈は Gradle の失敗後に出る
案（2026-10-17 の判断: やらない）
// IDE が PSI で DSL を読み、打っている最中に誤りへ下線"feature" / "*" / ...      // ← 下線「capture() で名前を付けて」// 役割名・group 名の補完、打鍵ごとの再評価も同じ枠// やらない理由: 任意の Kotlin を辿る必要があり katachi の判定と食い違う// 役割名を参照する場所が DSL に無い。評価には Gradle が要る
リスク・デメリット
  • 利用者PSI で読む検査は Kotlin の評価と一致しない（/ の連鎖・ヘルパー関数・外側の capture() { } を辿れない）ので、偽の警告や見逃しが出る
  • 利用者打鍵ごとの再評価は定義の評価に Gradle（コンパイル + JVM）が要るので、IDE が重くなる
  • ライブラリDSL の意味をプラグイン側に二重実装することになり、DSL を変えるたびに両方直す。Kotlin プラグインの PSI API（K1/K2）への依存が増える
