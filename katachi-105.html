KATACHI-105CI ベンチの比較方法の改善（同じ runner で HEAD~1 と HEAD、3 回測定・中央値）

CI のベンチは push ごとに別の runner で測った値を過去の値と比べるので、runner の CPU の違いだけで「遅くなった」と誤報が出る

今
push → ubuntu-latest で 1 回測る → 前回の push の値（別の runner）と比べるubuntu-latest の CPU は 5 種類ほど。同じコードでも 1.5 倍ぶれる閾値 150% で push の 15% 前後が誤報（benchmark-ci.md の見積り）
案（Metro 型、2026-10-02 の相談・決定ではない）
同じ runner の中で HEAD~1 と HEAD を両方測るそれぞれ 3 回測って中央値で比べる測る前に Gradle daemon を止めて条件をそろえる// 閾値は 150% のまま（KATACHI-106 は見送り）
リスク・デメリット
  • 利用者（利用者 = katachi の開発者）CI の時間が 2〜6 倍に延びる。PR の待ち時間が増える
  • ライブラリHEAD~1 のビルドが壊れている・依存が変わったときの扱いを決める。GitHub Actions の分数を多く使う
