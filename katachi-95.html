KATACHI-95役割・group 上の違反数 Code Vision と複数誤りのまとめ表示

定義側を見ても「この Role に今いくつ違反があるか」は分からない。定義の誤りも 1 回に 1 つしか出ない

今
"ViewModel".role {          // 定義側。違反の数は見えない  ktFileContent { ... }}// 違反は各ファイルの下線と ◆ のツールチップで 1 件ずつ見る// 定義の誤りは katachi が最初の 1 つで止まるので、直すたびに次が出る
案（2026-10-17 の判断: やらない）
 3 violations · 12 files      ← Code Vision（定義の上に数を出す）"ViewModel".role {  ktFileContent { ... }}// 定義の誤りを止めずに続け、まとめて出す// 判断の理由: ◆ のツールチップと注釈で足りる。続けると巻き添えの誤りが出る
リスク・デメリット
  • 利用者Code Vision の数は最後に check を回した時点の値なので編集中は古い。数だけ見て「直った」と誤解する
  • 利用者定義の誤りをまとめて出すと、最初の誤りの巻き添えで出た誤りも並び、どれから直すか分かりにくい
  • ライブラリ違反を Role ごとに集計する経路（SARIF → Role）と、定義の Role 宣言位置（PSI）を結ぶ処理が要る。Code Vision を 1 つに絞った設定も増える
