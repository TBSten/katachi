KATACHI-96調査: ガターに build.gradle.kts の hook 制約が出るか

build.gradle.kts に書いた制約がガターに出るか未確認。.kts は IDE では KotlinScript 扱いで、.kt と PSI の構造が違う可能性がある

今
// feature/home/build.gradle.ktsplugins { id("katachi.feature") }   // ← 制約があっても ◆ が出るか不明// 今の E2E fixture は *.kt だけ// .kts も KtFile だが、宣言は KtScript の子要素に入る
やること（調査まで）
1. .kts を含む fixture を取り直す（sample の build.gradle.kts に制約を足す）2. 出なければ: KtScript の子要素を走査する対応を入れる   or 「.kts は対象外」と決めて docs に書く// どちらにするかは調査結果を見てから
リスク・デメリット
  • 利用者出ないまま放置すると「.kt では光るのに .kts では光らない」のがバグに見える
  • ライブラリ.kts 対応を入れると Gradle Kotlin DSL の暗黙 import・スクリプト定義の解決が絡み、テストの fixture が重くなる（推測）
